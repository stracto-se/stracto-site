物理構成図と論理構成図の違い

物理構成図と論理構成図は、同じネットワークを異なる視点から表したものです。物理構成図は「何が、どこに、どう接続されているか」を確認するための図で、論理構成図は「どのネットワークに属し、どの経路で通信するか」を確認するための図です。

PHYSICAL配線・接続を見る

機器、ポート、リンク、速度、冗長化などを表します。

LOGICAL通信関係を見る

VLAN、Subnet、Gateway、L3境界などを表します。

FLOW両方を組み合わせる

構築・レビュー・障害切り分けで、2つの図を相互に参照します。

1. 物理構成図に書くもの

物理構成図では、ネットワーク機器同士が実際にどのポートで接続されているかを中心に整理します。今回ベースにした設計書でも、コアスイッチ、アクセススイッチ、ルータ、ファイアウォール、無線APなどを配置し、それぞれの接続ポートとリンク速度を記載していました。

  • 機器名・役割：Core Switch、Access Switch、Router、Firewall、APなど
  • 接続ポート：Gi1/0/1、WAN1、Port1など
  • リンク速度：100M、1G、10Gなど
  • リンク本数：LAGやEtherChannelなど、複数リンクの束ね方
  • 接続先：どの機器のどのポートとつながっているか
PHYSICAL DIAGRAM — LABEL EXAMPLE
Core-SW Gi1/0/1
        │ 1Gbps
        │
Access-SW Gi1/0/24

Firewall Port1
        │ 1Gbps x2 / LAG
        │
Core-SW Gi1/0/23-24

障害時に「どのケーブル・ポートを確認するか」をすぐ判断できるように、ポート番号やリンク速度は物理構成図へ集約しておくと便利です。

2. 論理構成図に書くもの

論理構成図では、物理ポートよりもVLAN、IPセグメント、Gateway、Firewall境界などの通信上の関係を整理します。今回の設計書では、管理用・ユーザー用・Firewall接続用など複数のネットワークを色分けし、それぞれのアドレス帯と主要なL3接続を示していました。

  • VLAN ID：どの論理ネットワークに属するか
  • IP Subnet：192.0.2.0/24 などのネットワーク範囲
  • Gateway：各SubnetのL3終端
  • L3接続：Core、Firewall、Router間のTransit Network
  • 外部接続：Internet、Cloud、VPNなど

192.0.2.0/24
GW 192.0.2.254
        │
     Core SW
        │

198.51.100.0/24
        │

論理構成図では、通信を理解するために必要な情報へ絞ることがポイントです。細かな物理ポート番号まで入れ始めると、物理図と情報が重複し、図が読みづらくなります。

3. どちらに何を書くかを決める

項目物理構成図論理構成図
機器名○○
型番必要に応じて記載通常は省略可能
Interface / Port○必要最小限
Link Speed○通常は省略
VLAN ID必要に応じて○
IP Subnet通常は省略○
Gateway通常は省略○
LAG / Redundant Link○構成上必要なら記載
図を見やすくするコツ：同じ情報を両方の図へ詰め込まず、「配線を確認するなら物理図」「通信を確認するなら論理図」と役割を分けると、図の情報量を抑えられます。

4. まず物理、次に論理の順で作る

ゼロからネットワーク構成を整理する場合は、最初に機器と接続関係を物理構成図として描き、その上でVLANやIPセグメントを論理構成図へ落とし込むと整理しやすくなります。

STEP 1Device / Port
物理接続
STEP 2VLAN / Subnet
論理分割
STEP 3Route / Policy
通信設計

この順番にすると、「このVLANはどの物理リンクを通るのか」「このFirewall接続はどのTransit Networkを利用するのか」といった対応関係を確認しながら設計できます。

5. ラベルは後工程で使う情報を優先する

構成図には多くの情報を載せられますが、すべてを書くと逆に見づらくなります。設計・構築・運用で実際に確認する情報を優先してラベルを付けると、使いやすい図になります。

用途あると便利な情報
構築機器名、Interface、VLAN、Subnet
レビュー役割、Zone、Gateway、冗長構成
障害切り分けPort、Link Speed、経路、管理ネットワーク
引き継ぎ機器役割、Network用途、主要な通信経路

例えば、物理図で「Gi1/0/24」と「1Gbps」、論理図で「VLAN 10 / 192.0.2.0/24」といったように、図の目的に合う情報だけを残すと確認が楽になります。

6. VLANや経路を色分けする

複数のネットワークが混在する場合は、VLANや通信系統ごとに色を分けると関係を追いやすくなります。今回の設計書でも、管理ネットワークや各Firewall系統などを色分けし、同じ色の経路を追うことで通信関係を把握できる構成になっていました。

VISUAL RULE — EXAMPLE
Blue   : Management Network
Red    : User / Internet Network
Green  : Firewall Transit
Purple : Service / Development Network

色だけに依存すると印刷時や閲覧環境によって区別しづらくなるため、VLAN IDやNetwork名も併記しておくと安全です。

7. 2つの図をセットでレビューする

物理構成図と論理構成図は別々に作りますが、レビューではセットで確認します。特に、物理リンクと論理ネットワークの対応がずれていないかを確認すると、構築時の設定ミスを減らしやすくなります。

  • Trunkで必要なVLANが通る構成になっているか
  • LAGのMember Portが物理図と一致しているか
  • FirewallのTrust / Untrust側が論理図と一致しているか
  • GatewayとRoutingの向きが論理図上で追えるか
  • 管理ネットワークから各機器へ到達できる構成になっているか

構築前に「物理的につながるか」と「論理的に通信できるか」を別々の図で確認しておくことで、現地作業や設定投入時の確認項目も整理しやすくなります。

設計を楽にする実務的なまとめ方

構成図は完成形を最初から細かく描くより、まず大枠を作ってから必要な情報を追加していく方が進めやすくなります。

01機器を配置
02接続を追加
03VLAN / IPを追加

物理図では「接続が分かること」、論理図では「通信が分かること」をゴールにすると、必要な情報を判断しやすくなります。また、構成変更が発生したときも、物理変更なのか論理変更なのかを分けて更新できるため、設計書の保守も楽になります。

まとめ

物理構成図は機器・ポート・リンクを確認するための図、論理構成図はVLAN・Subnet・Gateway・通信関係を確認するための図です。同じ情報を両方へ詰め込まず、それぞれの役割を分けることで読みやすくなります。

「物理接続 → VLAN / IP → Routing / Policy」の順で設計を進め、2つの図をセットでレビューすると、設計から構築、障害切り分けまで使いやすい資料になります。
