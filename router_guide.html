ルータとは

ルータは、IPアドレスを基に異なるネットワーク間の通信を中継する機器です。LAN内の端末からインターネットへ出る通信や、複数セグメント間の経路制御などで利用されます。

スイッチが同一ネットワーク内の接続を中心に担うのに対し、ルータは「どの宛先へ、どの経路を使って送るか」を判断する役割を持ちます。

POINT 01異なるネットワークを接続

LAN、WAN、各種セグメント間の通信を中継します。

POINT 02経路を選択

ルーティングテーブルを参照し、宛先ごとに次の転送先を決めます。

POINT 03外部接続を担当

PPPoEやNAT/PATを使い、内部ネットワークをインターネットへ接続できます。

ネットワークの中でどこに置かれるのか

Stractoの検証環境では、Cisco 891FJをインターネットルータとして使用していました。内部側では複数のファイアウォール向けネットワークを収容し、外部側ではPPPoEを使ってインターネット回線へ接続する構成です。

INTERNALCore / Firewall
Internal Network
ROUTERRouting / NAT
PPPoE
WANISP

この構成では、ルータが各内部ネットワークへの戻り経路を保持し、インターネット向け通信はデフォルトルートでWAN側へ転送します。

実務上のポイント：ルータは単に「インターネットにつなぐ機器」ではありません。経路、NAT、WAN接続方式、ACLなどを組み合わせ、内部ネットワークと外部ネットワークの境界で通信を正しく中継します。

ルータで必要になる基本設定

今回の実機設定では、管理インターフェース、内部側VLAN、PPPoE、スタティックルート、NAT/PAT、ACL、CBAC、SSH、NTP、Syslog、SNMPなどが設定されていました。

  • LAN / WANインターフェース：内部側と外部側の接続先を定義する
  • ルーティング：宛先ネットワークごとの転送先を設定する
  • デフォルトルート：個別経路がない通信の出口を定義する
  • PPPoE：ISPへの接続に必要なDialerインターフェースを構成する
  • NAT / PAT：内部アドレスを外部アドレスへ変換する
  • ACL：管理通信やWAN側の受信通信を制御する
  • 状態管理：必要に応じて戻り通信を動的に許可する
  • SSH / NTP / Syslog / SNMP：安全な管理と運用監視を行う

スタティックルートとデフォルトルート

ルータはルーティングテーブルを基に、宛先IPアドレスに応じて次の転送先を決定します。小規模な構成では、経路を手動で定義するスタティックルートが分かりやすく、運用もしやすい場合があります。

CONFIG EXAMPLE — STATIC ROUTE
ip route 192.0.2.0 255.255.255.0 198.51.100.1
ip route 203.0.113.0 255.255.255.0 198.51.100.2

今回の実機では、内部の各ネットワークに対して複数のスタティックルートが設定され、ファイアウォール側のアドレスをNext Hopとしていました。

デフォルトルート

CONFIG EXAMPLE — DEFAULT ROUTE
ip route 0.0.0.0 0.0.0.0 Dialer1

0.0.0.0/0は、より具体的な経路が存在しない宛先に対して使用されます。実機ではインターネット向けのデフォルトルートをPPPoE用Dialerインターフェースへ向けていました。

PPPoEによるインターネット接続

今回の検証環境では、物理WANポートでPPPoEを有効化し、実際のIPアドレスやPPP認証はDialerインターフェース側で処理する構成でした。

CONFIG EXAMPLE — PPPoE
interface GigabitEthernet8
 description *** TO-INTERNET ***
 pppoe enable group global
 pppoe-client dial-pool-number 1
!
interface Dialer1
 mtu 1492
 ip address negotiated
 encapsulation ppp
 dialer pool 1
 ppp authentication chap callin
 ppp chap hostname example-user
 ppp chap password 0 ********

PPPoEではEthernet上にPPPセッションを確立します。実環境のユーザー名やパスワードは認証情報にあたるため、公開記事では必ずサンプル値へ置き換えます。

NAT / PATの設定

プライベートIPアドレスを利用する内部ネットワークからインターネットへ接続する場合、NATを使ってアドレスを変換します。1つのグローバルIPアドレスを複数端末で共有する方式がPATです。

CONFIG EXAMPLE — NAT / PAT
access-list 100 permit ip 192.168.10.0 0.0.0.255 any
!
interface Vlan10
 ip nat inside
!
interface Dialer1
 ip nat outside
!
ip nat inside source list 100 interface Dialer1 overload

実機では、複数の内部セグメントをACLで指定し、overloadを利用してDialerインターフェースのアドレスへPATしていました。

ACLと状態管理

ルータでもACLを利用して、管理通信やWAN側からの受信通信を制御できます。今回の実機では、WAN側に受信ACLを適用し、必要な通信のみを明示的に許可し、それ以外を拒否する構成でした。

CONFIG EXAMPLE — WAN ACL
ip access-list extended WAN-IN
 permit udp host 203.0.113.10 eq ntp any
 deny ip any any log
!
interface Dialer1
 ip access-group WAN-IN in

CBACによる戻り通信の制御

実機ではCBAC（Context-Based Access Control）も利用しており、TCP、UDP、ICMP、NTPなどの通信を検査し、内部から開始した通信の戻りトラフィックを動的に扱う構成でした。

CONFIG EXAMPLE — CBAC
ip inspect name CBAC tcp
ip inspect name CBAC udp
ip inspect name CBAC icmp
!
interface Dialer1
 ip inspect CBAC out
補足：CBACはCisco IOSの従来型ステートフルファイアウォール機能です。現在の新規設計では、専用ファイアウォールやZone-Based Firewallなど、機種・要件に応じた方式を選択します。

管理・監視のための設定

ルータはネットワークの出口を担うため、管理経路と監視も重要です。今回の実機では、専用の管理インターフェースにIPアドレスを設定し、SSHによる管理、NTP、Syslog、SNMPを利用していました。

CONFIG EXAMPLE — SSH MANAGEMENT
ip ssh version 2
!
line vty 0 4
 access-class MGMT in
 login local
 transport input ssh

管理ACLを使って接続元を限定することで、管理端末以外からのSSH接続を抑止できます。

NTPによる時刻同期

CONFIG EXAMPLE — NTP
clock timezone JST 9 0
ntp server 203.0.113.20 prefer

実機では外部NTPサーバと同期し、自身を内部向けNTPサーバとして利用する設定も行われていました。ルータ、スイッチ、ファイアウォールの時刻を揃えておくことで、障害発生時に各機器のログを時系列で追いやすくなります。

まとめ

ルータは、異なるネットワーク間の通信経路を制御し、LANとWANをつなぐ役割を持つ機器です。インターネット接続では、ルーティングだけでなくPPPoE、NAT/PAT、ACLなど複数の機能を組み合わせることがあります。

今回の実機構成では、Cisco 891FJ上でスタティックルート、デフォルトルート、PPPoE、PAT、ACL、CBAC、SSH、NTP、Syslog、SNMPなどを利用していました。

本記事は「ネットワーク基礎シリーズ」の第3回です。次回はファイアウォールを取り上げ、Security Zone、Policy、NAT、通信制御などの基本を解説します。
