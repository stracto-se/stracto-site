コアスイッチとは

企業ネットワークや検証環境では、PCや無線アクセスポイントを収容するアクセススイッチ、外部ネットワークとの境界を担うファイアウォールやルータなど、複数のネットワーク機器が使われます。

コアスイッチは、それらの機器やネットワークセグメントを集約し、ネットワーク内部の通信を中継する中心的な役割を持つスイッチです。L3スイッチをコアとして利用する場合は、単なるL2転送だけでなく、VLAN間ルーティングやスタティックルーティングも担当できます。

POINT 01通信を集約する

アクセススイッチ、Firewall、Routerなど複数機器の接続点になります。

POINT 02ネットワークを分ける

VLANを利用し、管理用・利用者用・検証用など用途ごとに分離できます。

POINT 03異なるNWをつなぐ

L3機能を持つ機器では、SVIやルーティングを使ってセグメント間通信を制御できます。

アクセススイッチが端末を収容するのに対し、コアスイッチはネットワーク機器同士を接続し、複数のVLANやセグメントを束ねる位置に置かれます。

実務上のポイント：「高性能なスイッチだからコア」と決まるわけではありません。ネットワーク全体の中で、どの通信を集約し、どこでL2/L3の境界を作るかという役割から考えることが重要です。

アクセススイッチとの違い

項目 コアスイッチ アクセススイッチ
主な役割 ネットワーク内部の通信を集約 PCやAPなどの端末を収容
主な接続先 Firewall、Router、Switchなど PC、Server、AP、各種端末など
VLAN 複数VLANを集約することが多い 端末を用途ごとのVLANへ収容する
ルーティング L3スイッチでは担当する場合がある L2アクセスが中心の構成も多い

コアスイッチで必要になる基本設定

実際にコアスイッチを構築する場合は、機器を接続するだけではなく、役割に応じた設定が必要です。Stractoの検証環境では、VLAN、Trunk、SVI、IP Routing、スタティックルート、DHCP、SSH、NTP、Syslog、SNMPなどを設定しています。

  • ホスト名・管理IP：機器を識別し、管理ネットワークから接続できるようにする
  • VLAN：用途ごとにL2ネットワークを論理分割する
  • Access / Trunk：接続先に応じてポートの動作を決める
  • SVI：VLANごとのL3インターフェースを作成する
  • IP Routing / Static Route：異なるネットワーク間の経路を定義する
  • DHCP：VLANごとにIPアドレス、デフォルトゲートウェイ、DNSなどを端末へ配布する
  • SSH：管理端末から安全にCLIへ接続する
  • NTP：ログや障害解析のため機器の時刻を同期する
  • Syslog / SNMP：ログ収集や状態監視を行う

VLANとSVIの設定

VLANは、1台の物理スイッチ上に複数の論理ネットワークを作る仕組みです。Stractoの検証環境でも、管理用、インターネット接続用、開発・検証用など、用途に応じて複数のネットワークを分離しています。

VLANの作成

実際の設定パターンを一般化すると、Cisco IOSでは次のようにVLANを作成します。

CONFIG EXAMPLE — VLAN
vlan 10
 name USER-LAN
!
vlan 20
 name FIREWALL-LAN

SVIの作成

L3スイッチでVLANのデフォルトゲートウェイを持たせる場合は、SVI（Switch Virtual Interface）を作成します。

CONFIG EXAMPLE — SVI
ip routing
!
interface Vlan10
 description *** USER-LAN ***
 ip address 192.0.2.254 255.255.255.0
 no shutdown

ip routingを有効化することで、L3スイッチとしてルーティングを行えるようになります。実環境では設計要件に応じて、ACLやFirewall側のポリシーも含めて通信可否を設計します。

DHCPサーバとしての機能

コアスイッチは、L2/L3の集約やルーティングだけでなく、構成によってはDHCPサーバとして動作させることもできます。Stractoの検証環境では、Catalyst 3750X上に複数のDHCPプールを定義し、各VLANの端末へIPアドレスを自動配布しています。

DHCPプールでは、払い出すネットワークに加えて、デフォルトゲートウェイ、DNSサーバ、リース期間などを指定します。また、DHCPで払い出さないアドレス範囲は、ip dhcp excluded-addressで明示的に除外しています。

CONFIG EXAMPLE — DHCP SERVER
ip dhcp excluded-address 192.0.2.50 192.0.2.254
!
ip dhcp pool USER-LAN
 network 192.0.2.0 255.255.255.0
 default-router 192.0.2.254
 dns-server 192.0.2.53
 lease infinite

この例では、ip dhcp excluded-addressで固定利用するアドレス範囲を除外し、ip dhcp poolで端末へ配布する情報を定義しています。Stractoの検証環境では複数のネットワークに対して同様のDHCPプールを設定しています。

AccessポートとTrunkポート

Accessポート

Accessポートは、基本的に1つのVLANに所属させるポートです。端末や単一セグメントの機器を接続するときに使用します。

CONFIG EXAMPLE — ACCESS PORT
interface GigabitEthernet1/0/10
 description *** ACCESS-DEVICE ***
 switchport access vlan 10
 switchport mode access
 switchport nonegotiate

Trunkポート

Trunkポートは、1本のリンク上で複数のVLANを扱うために使用します。スイッチ間接続や、複数VLANを扱うFirewallなどとの接続で利用されます。

CONFIG EXAMPLE — TRUNK PORT
interface GigabitEthernet1/0/1
 description *** TO-ACCESS-SW ***
 switchport trunk encapsulation dot1q
 switchport trunk allowed vlan 10,20
 switchport mode trunk
 switchport nonegotiate

Stractoの検証環境でも、アクセススイッチ側やFirewall側との接続にTrunkを利用し、通過させるVLANを限定しています。

ルーティングの設定

コアスイッチがL3機能を担当する場合、VLAN間だけでなく外部ネットワークへの経路も定義します。Stractoの検証環境では、動的ルーティングではなくスタティックルーティングを採用しています。

CONFIG EXAMPLE — STATIC ROUTE
ip route 0.0.0.0 0.0.0.0 192.0.2.1
ip route 198.51.100.0 255.255.255.0 192.0.2.2

1行目はデフォルトルートの例です。個別に登録されていない宛先への通信を、上位のFirewallやRouterへ転送するように設定します。

設計上のポイント：スタティックルートは構成が分かりやすい一方、経路数や冗長構成が増えると運用が複雑になります。ネットワーク規模に応じてOSPFやBGPなどの動的ルーティングを検討します。

管理・監視のための設定

通信を転送できるだけでは運用できません。障害発生時に状態を確認できるよう、管理経路、時刻同期、ログ、監視の仕組みも準備します。

SSHによる管理

CONFIG EXAMPLE — SSH
ip ssh version 2
!
line vty 0 4
 login local
 transport input ssh

NTPによる時刻同期

CONFIG EXAMPLE — NTP
clock timezone JST 9 0
ntp server 192.0.2.10 prefer

Stractoの検証環境ではNTP同期状態は正常で、コアスイッチはネットワーク内のNTPサーバと時刻同期しています。ログの時刻が揃っていることは、障害解析や変更履歴の確認で重要です。

また、Stractoの検証環境ではSyslogとSNMPも設定しています。監視対象や通知方法は環境ごとに異なりますが、コアスイッチのような中心機器ほど「異常を検知できること」まで含めて設計する必要があります。

まとめ

コアスイッチは、アクセススイッチやFirewallなどを接続し、複数のネットワークを束ねる中心的な機器です。L3スイッチを利用する場合は、VLAN間ルーティングや外部ネットワークへの経路制御も担当できます。

最初に押さえておきたいのは、VLAN、Access / Trunk、SVI、ルーティング、DHCP、SSH、NTP、監視といった基本設定です。それぞれの設定を個別に覚えるだけでなく、「ネットワーク全体の中で、この機器に何を担当させるのか」を整理して設計することが重要です。

本記事は「ネットワーク基礎シリーズ」の第1回です。次回は、PCや無線APなどの端末を収容するエッジスイッチ（アクセススイッチ）を取り上げ、その役割と基本設定を解説します。

シリーズでは、このあとルータ、ファイアウォールと続き、ネットワークを構成する主要機器を内側から外側へ順番に整理していきます。
