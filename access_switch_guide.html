アクセススイッチとは

アクセススイッチは、PC、サーバ、無線アクセスポイント、プリンタなどの端末をネットワークへ接続するためのスイッチです。一般的にはネットワークの末端側に配置され、利用者や各種機器が最初に接続するポイントになります。

コアスイッチが複数のネットワークやネットワーク機器を集約するのに対し、アクセススイッチは「端末をどのネットワークへ収容するか」を担うことが主な役割です。

POINT 01端末を収容する

PC、Server、APなどの機器を有線LANへ接続します。

POINT 02VLANへ割り当てる

接続ポートごとに適切なVLANへ端末を収容します。

POINT 03上位SWへ集約する

Trunkなどを使い、複数VLANの通信をコアスイッチ側へ転送します。

ネットワークの中でどこに置かれるのか

Stractoの検証環境では、Cisco Catalyst 3750Gをエッジアクセススイッチ、Catalyst 2960Xを監視用アクセススイッチとして使用しています。上位のコアスイッチやファイアウォールと接続し、端末や各種ネットワーク機器を収容する構成です。

アクセススイッチでは、接続する端末に応じてAccess VLANを設定し、必要に応じて上位スイッチとの接続をTrunkにします。つまり、利用者側のネットワークとコア側のネットワークをつなぐ入口として機能します。

実務上のポイント：アクセススイッチは単に「LANケーブルを挿す機器」ではありません。端末をどのVLANへ所属させるか、未使用ポートをどう扱うか、上位リンクをどう設計するかなど、ネットワーク設計を実際の接続へ落とし込む重要な役割があります。

アクセススイッチで必要になる基本設定

アクセススイッチでは、端末を正しいネットワークへ収容し、上位スイッチへ安全に通信を渡すための設定が中心になります。

  • ホスト名・管理IP：スイッチを識別し、管理ネットワークから接続できるようにする
  • VLAN：利用者用、管理用、サーバ用など必要なVLANを作成する
  • Accessポート：端末を特定のVLANへ収容する
  • Trunkポート：上位スイッチへ複数VLANを転送する
  • STP：L2ループを防止し、安定したネットワークを維持する
  • 未使用ポート：不要なポートをshutdownし、意図しない接続を防ぐ
  • SSH：管理端末からCLIへ安全に接続する
  • NTP / Syslog / SNMP：時刻同期、ログ収集、監視を行う

Accessポートの設定

PCや無線APなど、1つのVLANだけを利用する機器を接続する場合はAccessポートを使用します。Stractoの検証環境では、利用者向けポートや無線AP向けポートをVLAN 10、管理系の接続をVLAN 2へ割り当てています。

以下は、実機設定の構成を保ちながらインターフェース名や説明、VLAN用途を公開用に一般化した例です。

REAL CONFIG PATTERN — ACCESS PORT
interface GigabitEthernet1/0/1
 description *** USER-ACCESS ***
 switchport access vlan 10
 switchport mode access
 switchport nonegotiate

switchport access vlanで所属VLANを指定し、switchport mode accessでAccessポートとして固定します。検証環境でも、端末やAPを接続するポートごとに用途に応じたVLANを明示的に設定しています。

上位スイッチとのTrunk接続

アクセススイッチからコアスイッチへVLANの通信を渡す場合はTrunkポートを使用します。検証環境では、コアスイッチ向けの複数ポートを802.1Q Trunkとして構成し、通過させるVLANを明示的に限定しています。

REAL CONFIG PATTERN — TRUNK PORT
interface GigabitEthernet1/0/21
 description *** TO-CORE-SW ***
 switchport trunk encapsulation dot1q
 switchport trunk allowed vlan 10
 switchport mode trunk
 switchport nonegotiate
 channel-group 1 mode on

switchport trunk allowed vlanを使うことで、Trunk上を通過させるVLANを限定できます。この構成では、アクセス側からコア側へ必要なVLANだけを転送する設計にしています。

EtherChannelで上位リンクを束ねる

Stractoのアクセススイッチでは、コアスイッチとの接続に4本のGigabit Ethernetを使用し、それらを1つのPort-channelとして束ねています。複数の物理リンクを論理的な1本のリンクとして扱う仕組みがEtherChannelです。

REAL CONFIG PATTERN — ETHERCHANNEL
interface Port-channel1
 description *** TO-CORE-SW ***
 switchport trunk encapsulation dot1q
 switchport trunk allowed vlan 10
 switchport mode trunk
 switchport nonegotiate
!
interface GigabitEthernet1/0/21
 channel-group 1 mode on
!
interface GigabitEthernet1/0/22
 channel-group 1 mode on

検証環境ではmode onによる静的EtherChannelを使用しています。構築時は、対向機器側でも同じチャネル構成・VLAN設定になっていることを確認する必要があります。

確認ポイント：EtherChannelのメンバーポートでVLAN設定などに差異があると、ポートがチャネルへ正常に参加できないことがあります。設定後はshow etherchannel summaryなどで状態を確認します。

STPとL2ループ対策

スイッチを複数台接続する環境では、物理的な接続方法によってL2ループが発生する可能性があります。STP（Spanning Tree Protocol）は、冗長なL2経路を制御し、ループを防ぐための代表的な仕組みです。

検証環境では、STPモードとしてRapid-PVSTを設定しています。

REAL CONFIG PATTERN — STP MODE
spanning-tree mode rapid-pvst
spanning-tree extend system-id

一方、検証環境固有の設定として一部VLANではSTPを無効化しています。この部分は一般的な推奨設定として掲載せず、実際のネットワークでは冗長経路やループ発生条件を整理したうえでSTP設計を行う必要があります。

未使用ポートの扱い

検証環境では、使用していない多数のインターフェースをshutdownしています。未使用ポートを無効化しておくことで、意図しない端末接続を防ぎ、実際に利用しているポートも把握しやすくなります。

REAL CONFIG PATTERN — UNUSED PORT
interface GigabitEthernet1/0/4
 switchport mode access
 shutdown

検証環境のshow interfaces statusでも、未使用ポートはdisabledとして確認できる状態です。

管理・監視のための設定

アクセススイッチもコアスイッチと同様に、管理用IP、時刻同期、ログ収集、監視の設定を用意します。検証環境では管理用VLANにIPアドレスを設定し、NTPの送信元にもそのVLANを利用しています。

REAL CONFIG PATTERN — MANAGEMENT
interface Vlan2
 description *** MANAGEMENT ***
 ip address 192.0.2.20 255.255.255.0
!
ip default-gateway 192.0.2.1
!
ntp source Vlan2
ntp server 192.0.2.10 prefer

検証環境ではSyslogサーバへのログ転送とSNMPによる監視も設定しており、NTPも正常に同期しています。障害解析では、スイッチ単体の設定だけでなく「いつ・どのポートで・何が起きたか」を追える状態にしておくことが重要です。

管理アクセスについて：この検証環境では、VTYにSSH以外も許可する設定が残っています。現在新規に構築する場合は、管理アクセスをSSHなどの暗号化方式へ限定することを推奨します。

まとめ

アクセススイッチは、PCや無線APなどの端末をネットワークへ収容し、適切なVLANへ接続する役割を持つ機器です。上位のコアスイッチとはTrunkなどで接続し、利用者側の通信をネットワーク全体へ受け渡します。

Access VLAN、Trunk、EtherChannel、STP、未使用ポートの管理、NTP、ログ・監視といった基本設定を押さえることで、安定したアクセスネットワークを構成しやすくなります。

本記事は「ネットワーク基礎シリーズ」の第2回です。次回はルータを取り上げ、異なるネットワーク間の通信やインターネット接続、スタティックルート、デフォルトルートなどの基本を解説します。
