Prisma Accessとは

Prisma Accessは、リモートユーザーや拠点からの通信をクラウド側へ収容し、共通のセキュリティポリシーを適用できるサービスです。

ユーザーが社外から接続する場合、拠点ネットワークを接続する場合、データセンターや本社側のリソースへアクセスする場合など、用途に応じて複数の接続形態を組み合わせます。

POINT 01クラウドでセキュリティを提供

ユーザーや拠点の通信に対して、クラウド側で共通のセキュリティポリシーを適用します。

POINT 02複数の接続形態に対応

リモートユーザー、拠点、データセンターなど、接続対象に応じて構成を分けます。

POINT 03一元的なポリシー管理

利用場所が異なるユーザーやネットワークでも、共通の考え方でアクセス制御を行えます。

主な構成要素とセキュリティ機能

Prisma Accessでは、接続する対象に応じてMobile Users、Remote Networks、Service Connectionなどを使い分けます。

あわせて、Webアクセスや脅威対策などのセキュリティ機能を組み合わせ、利用環境に合わせたポリシーを設計します。

CONNECTIVITY接続対象に応じた構成

リモートユーザー、拠点、データセンターなど、それぞれの接続目的に合わせて構成します。

SECURITY通信をクラウド側で保護

URL Filtering、DNS Security、Threat Preventionなどの機能を組み合わせて通信を保護します。

Prisma Accessの管理方法

Prisma Accessの設定・運用には、主に Strata Cloud Manager と Panorama の2つの管理方式があります。どちらを利用するかによって、設定画面や設定反映の手順が異なります。

クラウド側で一元管理する場合はStrata Cloud Managerを利用します。一方、既存の次世代ファイアウォールをPanoramaで管理しており、共通ポリシーを含めて運用したい場合は、PanoramaのCloud Servicesプラグインを利用してPrisma Accessを管理できます。

CLOUD MANAGEMENTStrata Cloud Manager

Webベースの管理画面から、Prisma Accessの設定、セキュリティポリシー、接続構成、運用状況などを一元的に管理します。設定変更後はPush ConfigでPrisma Accessへ反映します。

PANORAMA MANAGEMENTPanorama

Cloud Servicesプラグインを利用してPrisma Accessを管理します。既存のPalo Alto Networks製ファイアウォールとあわせて運用する環境で利用され、設定変更はCommit and PushでPrisma Accessへ反映します。

日常運用で確認する主なポイント

  • セキュリティポリシー：許可・拒否ルール、URL Filtering、Threat Preventionなどの設定内容を確認します。
  • 接続状態：Mobile Users、Remote Networks、Service Connectionなどの接続状況や異常の有無を確認します。
  • ログと脅威情報：Traffic、Threatなどのログを確認し、ブロックされた通信や不審なイベントを調査します。
  • ユーザーと端末：GlobalProtectを利用するユーザーや接続端末の状態を確認し、認証やアクセス制御の問題を切り分けます。
  • 設定変更の反映：変更内容を確認したうえで、Strata Cloud ManagerではPush Config、PanoramaではCommit and Pushを実行し、Prisma Accessへ反映します。
運用上のポイント：Panorama管理のPrisma Accessでも、可視化や監視の多くはStrata Cloud Managerから利用できます。設定を行う場所と、監視・状態確認を行う場所が異なる場合があるため、自環境の管理方式を把握しておくことが重要です。

ADEMによるユーザー体験の監視

Autonomous Digital Experience Management（ADEM）は、Prisma Accessと組み合わせて利用できる監視・可視化機能です。ユーザー端末からアプリケーションまでの通信経路を継続的に確認し、通信品質やアプリケーション利用時の問題を切り分けるために利用します。

GlobalProtectを利用するMobile Usersでは、端末、Wi-Fi／LAN、インターネット、Prisma Access、アプリケーションまでの各区間を可視化し、どこでユーザー体験が低下しているかを確認できます。

END-TO-END VISIBILITY通信経路を可視化

ユーザー端末からアプリケーションまでの各区間を確認し、ネットワークやアプリケーションのどこに問題があるかを切り分けます。

SYNTHETIC MONITORING通信品質を継続的に確認

合成テストを利用して、遅延、ジッタ、パケットロスなどのネットワーク品質やアプリケーションの応答状況を継続的に監視します。

ADEMはPrisma Accessと連携する追加機能で、利用には契約しているサービスやライセンスに応じた有効化が必要です。

代表的な利用イメージ

Prisma Accessは、ユーザーや拠点の場所に依存せず、クラウド側でアクセス制御を行いたい場合に利用されます。

  • リモートアクセス：社外のユーザーから業務システムやインターネットへ安全にアクセスさせる。
  • 拠点接続：支店や営業所など複数拠点の通信へ共通のセキュリティポリシーを適用する。
  • 内部リソース接続：データセンターや本社側にあるアプリケーションへ必要な通信経路を用意する。
  • インターネット保護：WebアクセスやDNS、脅威対策などのセキュリティ機能をクラウド側で適用する。

GlobalProtectとの関係

GlobalProtectは、リモートユーザーがPrisma Accessへ接続する際に利用されるクライアントです。

ユーザー認証や端末情報、セキュリティポリシーと組み合わせることで、社外からのアクセスを安全に制御できます。

REMOTE ACCESS社外からの接続

リモートユーザーの通信をPrisma Accessへ収容し、必要なセキュリティ制御を適用します。

POLICY認証・端末情報と連携

ユーザー認証や端末状態などの情報を、アクセス制御の判断材料として利用できます。

認証とアクセス制御

Prisma Accessでは、利用環境に応じて外部認証、SAML、LDAP、クライアント証明書、多要素認証などを組み合わせることができます。

代表的な構成として、Microsoft Entra IDとCloud Identity Engine（CIE）を組み合わせる方法や、社内のActive Directory（AD）サーバーへLDAP／LDAPSで認証する方法があります。

CLOUD IDENTITYEntra ID ＋ Cloud Identity Engine

Microsoft Entra IDをCloud Identity Engineと連携し、ユーザーやグループ情報をPrisma Accessで利用します。SAMLなどの認証と組み合わせることで、クラウド側のID基盤を利用したGlobalProtectユーザー認証や、ユーザー／グループ単位のポリシー制御が可能です。

ON-PREMISES IDENTITYADサーバー ＋ LDAP／LDAPS

社内のActive Directoryを認証基盤として利用する場合は、LDAP Server ProfileとAuthentication Profileを作成し、GlobalProtectのPortal／GatewayからADへ認証を行います。実運用では、認証通信の到達性とLDAP over SSL/TLS（LDAPS）の利用を考慮します。

上記は代表例です。Prisma Access／GlobalProtectでは、環境に応じてSAML、RADIUS、LDAP、クライアント証明書、ローカル認証など複数の方式を選択できます。

ユーザーだけでなく、接続元端末の情報も含めてアクセス条件を設計することで、より細かなアクセス制御が可能です。

IDENTITYユーザーを確認する

既存の認証基盤と連携し、利用者を確認したうえでアクセスを許可します。

DEVICE端末情報も考慮する

必要に応じて端末状態をアクセス条件へ組み込み、ポリシーを細かく設計できます。

端末状態を考慮したアクセス制御

Prisma Accessでは、ユーザー認証だけでなく、接続している端末の状態をポリシー判断に利用できます。

例えば、管理対象端末かどうか、必要なセキュリティ条件を満たしているかといった情報を利用し、アクセス先に応じて許可・制限を設計します。

ポイント：「誰が接続しているか」だけでなく、「どのような端末から接続しているか」も含めてアクセスを判断できる点が、クラウド型セキュリティサービスの重要な考え方です。

通信経路をどう設計するか

Prisma Accessを利用する場合も、すべての通信を同じ宛先へ送るわけではありません。

インターネット向け通信、社内リソース向け通信、拠点間通信など、通信先に応じて適切な経路を設計します。

実際の経路設計は、利用する接続方式、拠点構成、認証基盤、既存ネットワークとの接続方法によって変わります。

まとめ

Prisma Accessは、リモートユーザーや拠点の通信をクラウド側へ収容し、共通のセキュリティポリシーを適用するためのサービスです。

まずは、Mobile Users、Remote Networks、Service Connectionの役割を押さえると、全体構成を理解しやすくなります。

そのうえで、GlobalProtect、Entra ID＋Cloud Identity EngineやAD＋LDAP／LDAPSなどの認証方式、端末情報、通信経路を組み合わせ、利用環境に合ったアクセス制御を設計します。

運用時は、自環境がStrata Cloud Manager管理かPanorama管理かを把握し、ポリシー、接続状態、ログ、設定反映の流れを整理しておくことが重要です。さらにADEMを利用することで、ユーザー端末からアプリケーションまでの通信品質やユーザー体験を可視化し、問題箇所の切り分けに活用できます。
