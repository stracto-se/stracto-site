VLAN・IPアドレス設計とは

VLAN・IPアドレス設計では、ネットワークをどの単位で分割し、それぞれにどのアドレス帯を割り当てるかを決めます。

設計書では、VLAN IDだけを決めるのではなく、用途、IP Subnet、Gateway、Access / Trunkの扱いまで対応づけておくと、構成図や機器設定との関係を追いやすくなります。

POINT 01用途で分ける

User、Management、Server、Transitなど、通信の役割ごとにネットワークを整理します。

POINT 02IPを対応づける

VLANごとにSubnetとGatewayを決め、アドレスの重複を避けます。

POINT 03接続方式まで書く

Access / Trunkや収容先を整理し、L2設計とL3設計をつなげます。

1. まずネットワークの用途を分ける

最初に、「何を同じネットワークへ収容し、何を分離するか」を決めます。用途が決まる前にVLAN番号だけを割り当てると、後から設計意図が分かりにくくなります。

  • User Network：PCなど利用者端末を収容するネットワーク
  • Management Network：ネットワーク機器の管理用通信を収容するネットワーク
  • Server / Service Network：サーバーやサービス用の通信を分離するネットワーク
  • Transit Network：ルータやファイアウォールなどL3機器間を接続するネットワーク
設計のポイント：VLANは単なる番号ではなく、「通信をどの単位で分離するか」を表す設計要素です。用途を先に決めると、Security PolicyやRoutingの設計にもつなげやすくなります。

2. VLANは「ID・IP・接続方式・用途」で一覧化する

第1回で紹介した設計書では、VLAN ID、IPアドレス、Access / Trunk、用途を同じ表で整理していました。この形式にすると、論理構成とスイッチ設定の対応を確認しやすくなります。

VLAN IDNetwork接続方式用途

20198.51.100.0/24Trunk / TransitFirewall Transit

公開記事では、IPアドレスはDocumentation用のサンプル値へ置き換えています。実環境では、既存ネットワークとの重複や将来拡張も確認したうえでアドレス帯を決めます。

3. IPアドレスは「Subnet・Gateway・利用範囲」で整理する

IPアドレス設計では、ネットワークアドレスだけでなく、Gatewayや機器・端末へ割り当てる範囲も決めておくと運用しやすくなります。

IP ADDRESS PLAN — EXAMPLE
VLAN 10 / User Network
  Network : 192.0.2.0/24
  Gateway : 192.0.2.254
  Client  : 192.0.2.10 - 192.0.2.199
  Reserve : 192.0.2.200 - 192.0.2.253

VLAN 30 / Management
  Network : 203.0.113.0/24
  Gateway : 203.0.113.254
  Device  : 203.0.113.10 - 203.0.113.99

固定IP、DHCP、将来利用する予約範囲などを分けておくと、機器追加やアドレス払い出し時の衝突を防ぎやすくなります。

4. Gatewayをどこに置くかを決める

各SubnetのGatewayをどの機器が持つかは、通信経路を決める重要な設計項目です。L3スイッチのSVIで終端するのか、ファイアウォールで終端するのかによって、RoutingやSecurity Policyの考え方も変わります。

5. Access / Trunkの役割を分ける

VLAN設計をスイッチ設定へ落とし込むために、端末を収容するAccess Portと、複数VLANを通すTrunk Portを整理します。

6. Transit Networkと管理ネットワークを分けて考える

ルータやファイアウォール間のTransit Networkは、ユーザー端末を収容するVLANとは目的が異なります。また、Management Networkも業務通信とは分離して設計すると、管理経路を整理しやすくなります。

  • Transit NetworkはL3機器間の接続に必要な範囲へ限定する
  • Management Networkは管理対象機器と管理元を明確にする
  • User / Server用VLANと管理用VLANを混在させない
  • 論理構成図とVLAN一覧で同じ名称・IDを使用する

7. 設計レビューで確認するポイント

VLAN・IPアドレス設計は、表だけを見るのではなく、物理構成図・論理構成図と合わせて確認します。

  • VLAN IDやSubnetが重複していないか
  • 各SubnetのGatewayが明確になっているか
  • Access / Trunkの扱いが構成図と一致しているか
  • 管理用・ユーザー用・Transit用の役割が分離されているか
  • 将来の機器追加やアドレス増加に必要な余地があるか
レビューの考え方：「VLAN表だけ正しい」ではなく、構成図、Gateway、Routing、Security Policyへ矛盾なくつながっていることを確認します。

まとめ

VLAN・IPアドレス設計では、VLAN IDだけでなく、用途、Subnet、Gateway、Access / Trunk、収容先をセットで整理すると、設計意図が伝わりやすくなります。

「用途を決める → VLANを分ける → IPを割り当てる → Gatewayと接続方式を決める」の順で整理すると、論理構成図やスイッチ設定へ落とし込みやすくなります。

次回は、VLAN・IP設計の上位にあるRoutingとSecurity設計を取り上げます。通信経路とFirewall Policyをどのように設計書へ整理するかを見ていきます。

記事について

本記事は、Stractoが保有していたネットワーク検証環境の設計書に含まれるVLAN・IPアドレス設計を基に、公開可能な内容へ一般化して構成しています。

元の設計書に含まれる実際のIPアドレス、VLAN名称、機器名などは掲載せず、記事内ではDocumentation用アドレスと一般名称へ置き換えています。
